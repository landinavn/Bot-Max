# Поздравление Деда Мороза для нескольких детей

Одна кнопка главного меню: **«🎅 Поздравление для нескольких детей»** (`cat_ded_moroz_family`). Пользователи видят заглушку и кнопку возврата. Полный сценарий доступен только настроенному `ADMIN_USER_ID`, включая проверку прямых callback-запросов и фонового задания. Покупка семейного варианта пока не подключена; тарифы поздравления для одного ребёнка остаются прежними.

## Порядок работы

1. Выбрать «2 ребёнка», «3 ребёнка» или «4 и больше», затем точное количество 4, 5 или 6. В первой версии поддерживаются 2–6 детей. При большем составе нужен отдельный вариант текста и проверка длительности.
2. Заполнить первого ребёнка: домашнее имя, возраст 0–17, пол, один факт, одно пожелание. Затем второго и остальных. Каждый вопрос подписан номером и уже введённым именем. Порядок задаёт родитель; бот его не меняет и не угадывает пол по имени.
3. Факт вводится как продолжение «ты …»: «любишь рисовать», «научилась плавать». Если подходящего факта нет, «пропустить» заменяется нейтральной фразой «очень стараешься». Пожелание — после «Желаю тебе …»: «интересных книг», «побед в футболе». Общий факт — после «вы …»: «помогаете маме». Бот показывает примеры и лимит у каждого вопроса.
4. Проверить сводку: все имена, возраст, пол, факты и пожелания. Любое поле можно исправлять **без запуска озвучки**. Выбранное для редактирования поле сохраняется в SQLite; после перезапуска открыть семейную кнопку снова. При повторяющихся пожеланиях выводится подсказка сделать их индивидуальными.
5. Нажать «✅ Всё верно, далее». Затем отправить одно общее фото или нажать «Продолжить без фото». Только после этого появляется задание озвучки. Повторное нажатие старой кнопки не создаёт вторую попытку.
6. Прослушать аудио, утвердить или изменить данные детей. Правится только выбранное поле; остальной текст и теги голоса восстанавливаются из шаблона. Для администратора остаются доступными повторные платные озвучки по явному нажатию.
7. После утверждения озвучки создаётся видео, затем локально добавляются заставка и музыка. Общее фото появляется в рамке, если оно было загружено. В варианте без фото ни изображение, ни пустая рамка не рисуются. В чат приходит MP4 как видео, с существующими действиями скачивания, компактной версии, отзыва и пересылки. «Сделать ещё» возвращает в семейный сценарий.

## Голос и длина

Используется существующий клон HeyGen «Дед мороз» и те же `DED_MOROZ_*` настройки скорости, понижения тона и эха. В семейном шаблоне сохранены `[deep voice]`, `[raspy]`, `[warm]`, `[drawls]`, `[proud]`, `[reassuring]`, `[pause]`, `[slightly excited]`, `[serious]` и начальное «Охо-хо-хо!». Новые параметры провайдеров и голосовые модели не вводятся. Возраст и пол используются для проверки и обращения; возраст не перечисляется в аудио.

Для 2–3 детей факт и пожелание — до 45 символов/6 слов, общий факт — 45/7. Для 4–6 детей — 28/3 и 30/4 соответственно. Имя — до 24 символов/2 слов. Весь текст без тегов — не больше 130 слов. Это ограничение текста, а не обещание точного хронометража: фактическая длительность MP3 измеряется перед утверждением и повторно перед видео. Запись, которая вместе с заставкой не помещается в 70 секунд, не запускает генерацию видео. Администратор получает предложение сократить данные. Полный MP4 также проверяется по длительности.

## Сохранность и статистика

Данные находятся в существующей таблице `ded_moroz_orders`, в `details` с `variant="family"` и фиксированными ключами `child_1_name`, `child_1_fact` и т. п. Версии MP3, утверждённая озвучка, видео провайдера и результаты сборки сохраняются существующим механизмом. Новый заказ не перезаписывает активное поздравление. Для уже активного заказа одного ребёнка сначала предлагается его закончить.

Очередь и защита от повторных платных POST используются прежние. После неоднозначного прерывания платный запрос автоматически не повторяется. Команда `python -m ded_moroz_rebuild ORDER_ID` поддерживает пересборку завершённого семейного заказа, в том числе без фото, из сохранённых видео и утверждённого аудио. Имена для заставки склоняются по отдельности; неизвестные формы не угадываются.

Счётчики `/stats`:

- `click_ded_moroz_family` — нажатия семейной кнопки;
- `dm_family_started` — созданные семейные заказы;
- `dm_family_children_2` … `dm_family_children_6` — состав семей при создании;
- `dm_family_video_created` — впервые выданные готовые семейные поздравления.

Клиентские нажатия и готовые результаты показаны отдельно от тестов администратора. Пересборка уже выданного заказа не увеличивает счётчик готовых поздравлений. Счётчики существующего одиночного сценария не смешиваются с семейными.

## Запуск и проверка

Новых переменных окружения и секретов нет. Нужны уже настроенные `ADMIN_USER_ID`, `HEYGEN_API_KEY`, существующий голос/аватар Деда Мороза, Object Storage, FFmpeg и музыкальные файлы. При обновлении сохранить базу и `studio_files`; после установки кода перезапустить бот. Отдельная миграция данных старых заказов не нужна.

Локальные проверки:

```bash
venv/bin/python -m pytest tests/test_ded_moroz*.py tests/test_heygen_tts.py tests/test_handlers.py tests/test_prodamus.py tests/test_sales_stats.py -q
```

Тесты заменяют платные API тестовыми ответами. FFmpeg проверяется на локальных коротких роликах: H.264/AAC, фактическая длительность аудио, заставка и отсутствие рамки при пропуске фото. Качество семейной интонации на выбранном голосе нужно оценить отдельным запуском администратора; автоматическая проверка не тратит баланс.
