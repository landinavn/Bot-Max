# Административное поздравление от Деда Мороза

Раздел доступен только `ADMIN_USER_ID`, независимо от `STUDIO_ENABLED`.
Остальные пользователи по-прежнему видят заглушку и «Назад».
Озвучка Деда Мороза — **Fish Audio**; анимация аватара — **HeyGen Avatar IV**.
Мультстудия «Маленькие чудеса Ани» сохраняет Yandex TTS. Обычные песни,
открытки, тарифы, платежи и балансы не меняются.

## Настройка

- `FISH_AUDIO_API_KEY` — API-ключ официального Fish Audio API.
- `FISH_AUDIO_VOICE_ID=fae6fa8fee9343049eecc1a1ffcb2acb` — выбранный голос;
  этот ID также является значением по умолчанию в коде. Другой голос автоматически
  не подставляется. Прежний `DED_MOROZ_VOICE_ID` ElevenLabs в этой ветке не читается.
- `FISH_AUDIO_MODEL=s2.1-pro` — модель по умолчанию, настраивается окружением.
  Автоматического переключения на бесплатную или другую модель нет.
- `HEYGEN_API_KEY` — только создание аватара и видео; для самого TTS не нужен.
- `DED_MOROZ_AVATAR_ID` — необязательно: готовый Photo Avatar **look ID**, не ID группы.
- `DED_MOROZ_REF_URL` — необязательно: публичный HTTPS URL референса Деда Мороза.
- Существующие `ADMIN_USER_ID`, параметры Yandex Cloud `STORAGE_*`, `STUDIO_FILES_DIR`.

Секреты задаются в окружении сервиса, не в чате. После изменения окружения
нужно перезапустить сервис. `YANDEX_TTS_API_KEY` веткой Деда Мороза не используется.
Автоматического отката на ElevenLabs или HeyGen TTS нет. Модуль
`elevenlabs_tts.py` и его независимые интеграции сохранены без изменения.

Медиа для видео (для создания озвучки не нужны):

```
examples/ded_moroz_ref.png       # не нужен при готовом look ID или REF_URL
examples/fire_overlay.mp4       # необязателен
examples/audio/jingle_bells.mp3
examples/audio/ny_music.mp3
```

Если огненного оверлея нет, монтаж пропускает огонь с предупреждением в логе.
Собственный снег программа не добавляет. Сами медиафайлы в изменение не входят.

## Сбор данных и озвучка

1. Администратор нажимает «Поздравление Деда Мороза» и вводит имя/ласковое обращение.
2. Приходят полный шаблон и последовательные вопросы об увлечении, достижении,
   качестве и задании на год. Фразы вставляются целиком, без изменения падежа.
3. Фото JPG/JPEG или PNG отправляется через «Файл». Pillow проверяет содержимое:
   до 20 МиБ и 40 000 000 пикселей. Исходник, PNG и публичная ссылка сохраняются.
   Есть копия `studio_files/ded_moroz_{user_id}/child_photo.png`; конкретный заказ
   использует собственный неизменяемый файл `studio_files/{order_id}/...`.
4. Начинается озвучка. Шаблон по-прежнему содержит «Охо-хо-хо!» и исходные теги,
   но **перед отправкой в Fish Audio** `clean_speech_text()` удаляет любые
   квадратные скобки и их содержимое, включая вложенные и неизвестные теги.
   `[pause]` превращается в многоточие; лишние пробелы и соседняя пунктуация
   нормализуются. Пример: `Здравствуй, [pause] Маша!` → `Здравствуй… Маша!`.
   Пустой после очистки текст не отправляется провайдеру.
5. Перед платным синтезом `FishAudioAdapter.check_voice()` выполняет
   `GET https://api.fish.audio/model/{FISH_AUDIO_VOICE_ID}` с
   `Authorization: Bearer {FISH_AUDIO_API_KEY}`. Проверяются точный `_id`,
   `type=tts`, готовность `state=trained` и отсутствие `dmca_taken_down`.
   401/403/404 или неготовый голос останавливают заказ с понятной причиной.
   Видимость `private` сама по себе не запрещена, если API разрешает доступ ключу.
6. Синтез — один `POST https://api.fish.audio/v1/tts`:
   заголовки `Authorization: Bearer …`, `Content-Type: application/json`,
   `model: s2.1-pro` (или явно настроенное значение).
   JSON: `text`, `reference_id` с выбранным ID голоса, `format=mp3`,
   `sample_rate=44100`, `mp3_bitrate=128`, `language=ru`.
   `language` управляет нормализацией русских чисел/дат, а не меняет тембр голоса.
   Кириллические имена и факты передаются без транслитерации; повторное
   соседнее «ты ты» удаляется на подготовке речи. Непроверенные теги провайдеру
   не отправляются. Качество произношения выбранного голоса проверяется на слух.
7. MP3 сохраняется как `{order_id}/speech-v{version}.mp3` и проверяется `ffprobe`.
   Для проверки нужен существующий пакет FFmpeg; необходимость проверяется до POST.
   Рядом сохраняется `speech-v{version}.fish.json` с хешем текста, голоса,
   модели и всех параметров запроса, хешем MP3 и фактической длительностью.
   API-ключей в метаданных нет. Повтор того же задания/версии использует
   проверенный файл без HTTP-запросов. Несовпадение параметров или повреждение
   файла останавливает заказ для проверки вместо перезаписи и новой оплаты.

   В SQLite сначала фиксируются путь и этап `audio_publish`, затем отдельным
   шагом выполняется загрузка в S3 и сохраняется публичный `audio_url`.
   Сбой S3 не вызывает новый TTS-запрос. При перезапуске после сохранения MP3,
   но до фиксации SQLite, готовая озвучка восстанавливается по проверенным
   метаданным без повторной платной генерации.

   В архиве `ded_moroz_audio_versions` хранятся исходный `text`, очищенный
   `submitted_text`, `voice_id`, `provider=fish_audio`, `model`,
   `request_sha256`, локальный путь и публичная ссылка. До публикации
   `provider_url` пуст, затем содержит URL MP3 в нашем S3.
8. Приходят очищенный текст и native audio с сообщением
   «🎧 Прослушайте озвучку Деда Мороза. Всё нравится?» и кнопками
   `dm_audio_approve`, `dm_audio_regenerate`, `dm_audio_edit`.

## Повторные попытки и одобрение

Администратору доступны неограниченные перегенерации и правки текста, включая
заказы с `edit_used=1`. Каждая принятая повторная попытка атомарно увеличивает
`regeneration_attempts` и записывает:
`Перегенерация аудио для USER_ID. Попытка: N`.
Начальная генерация не считается повторной. Для будущего обычного пользователя
сохраняется одна общая повторная попытка; публичный доступ не открывается.

Кнопки привязаны к ID сообщения MAX и версии. Старые/двойные нажатия не создают
новых платных запросов. При одобрении фиксируются `approved_audio_url` и
`approved_audio_path`. **Именно утверждённый MP3 Fish Audio** передаётся в
`POST /v3/videos` как `audio_url` и используется как речь при монтаже.
До одобрения видео не запускается. Старые `dm_audio_ok`/`dm_audio_edit` совместимы.
Повторный вход в раздел возвращает сохранённое аудио без новой генерации.

## Видео и монтаж

Photo Avatar создаётся один раз через `POST /v3/avatars`, сохраняются
`avatar_item.id` (look) и `avatar_group.id`. До готовности используется
`GET /v3/avatars/looks/{look_id}`. Затем `POST /v3/videos` получает look ID,
утверждённый `audio_url`, `engine.type=avatar_iv`, `aspect_ratio=16:9`,
`resolution=1080p`, `expressiveness=medium`. Результат получается через
`GET /v3/videos/{video_id}` и сохраняется локально.

FFmpeg: MP4 H.264/AAC, 1920×1080, 30 FPS, yuv420p, faststart.
Основная речь — утверждённый MP3 с нулевой секунды; длина определяется полной
озвучкой. Если видео короче, удерживается последний кадр. Голос не обрезается.

- Огонь/гирлянды через screen при наличии оверлея.
- Фото ребёнка справа внизу, ширина около 480 px, высота до 900 px, белая рамка,
  показ с 30% до 70% длины. В HeyGen фото ребёнка не передаётся.
- Jingle Bells: первые 3 секунды, громкость 0.4. Фоновая музыка: циклически, 0.2.
- Речь: громкость 1.0, `amix normalize=0` и ограничитель перегруза.
- Титр «Для {name} от Деда Мороза»: первые 5 секунд, через UTF-8 textfile.

Готовый MP4 сохраняется локально/S3 и отправляется как native video.
Токен MAX переиспользуется при повторной доставке. `dm_video_created`
учитывается один раз после подтверждённой отправки и показывается в `/stats`.

## Сохранность и восстановление

Миграции через `init_db()` только добавляют поля. Готовые озвучки, ролики и
версии не удаляются и автоматически не перегенерируются. Старые записи
архива получают `provider=legacy`; продолжается скачивание ранее полученных
HeyGen URL на сохранённом этапе `audio_download`. Все новые и явно повторные
синтезы используют Fish Audio. Старые озвучки ElevenLabs/HeyGen/Yandex остаются
доступными и автоматически не заменяются. Повторная сборка видео использует
утверждённый MP3 без вызова TTS; явная кнопка перегенерации создаёт новую версию.

Сбой S3, GET-опроса, монтажа или MAX повторяет сохранённый этап без нового TTS
или video POST. При аварии во время платного запроса с неопределённым ответом
заказ становится `manual`; автоматический повтор запрещён.
`/dm_resume ID_заказа` продолжает безопасный сохранённый этап либо GET-опрос по
известному video_id. Неизвестный платный POST требует сверки у провайдера.
Рекомендуется сохранять резервную копию всей SQLite-базы и `studio_files`.

## Таймауты и ошибки

Проверка голоса: таймаут 20 секунд, подключение 8 секунд. Синтез: подключение
10 секунд, запись 30 секунд, чтение 180 секунд; весь цикл ограничен 240 секундами.
Ответ ограничен 30 МиБ. API-ключи и полные ответы провайдера в лог не выводятся.

401 — ключ/авторизация; 402 — баланс или доступ к платной модели; 403 — запрет
доступа; 404/409 — голос недоступен; 429 — лимит запросов. Оператор получает
причину, заказ переходит в `manual`. Автоматических повторов платного POST нет.
После исправления известного отклонения до принятия запроса `/dm_resume ID`
разрешает явную повторную попытку. Таймаут/обрыв после отправки POST или HTTP 5xx
с неизвестным результатом требуют сверки у Fish Audio перед новым запуском.
Неизвестные старые `manual`-заказы автоматически не разблокируются.

## Проверка доступа и запуск

На сервере задать три переменные Fish Audio выше, сохранить существующие
`HEYGEN_API_KEY` и `STORAGE_*`, выполнить обычное обновление проекта и
`systemctl restart botmax`. Ключи не коммитить. Доступ к голосу можно проверить
этой командой: она выполняет только GET и не генерирует аудио.

```bash
venv/bin/python -c 'import asyncio; from config import Config; from ded_moroz import Settings; from fish_audio_tts import FishAudioAdapter; s=Settings.from_config(Config.from_env()); d=asyncio.run(FishAudioAdapter(s.fish_key,s.voice_id,None,model=s.fish_model).check_voice()); print({k:d.get(k) for k in ("_id","state","type","visibility","licensed")})'
```

В доступном окружении разработки `FISH_AUDIO_API_KEY` отсутствует. Попытка
анонимного GET к указанному голосу не завершилась из-за сетевого `ProxyError`.
Это не является ответом Fish Audio о недоступности голоса: доступ аккаунта
и реальная речь выбранного голоса **пока не проверены**. Реальный платный POST
не запускался; голос не подменялся. Тесты используют подменённые HTTP-ответы,
синтетические воспроизводимые MP3 и реальный FFmpeg/ffprobe.

## Коммерческое использование

[Условия Fish Audio](https://fish.audio/terms/) предусматривают коммерческое
использование для Paid Services при соблюдении условий сервиса. Публичность
голоса сама по себе не подтверждает права на его коммерческое использование.
Для конкретного `fae6fa8fee9343049eecc1a1ffcb2acb` нужно уточнить разрешения
владельца/лицензию голоса и применимые условия аккаунта/модели у Fish Audio;
проверить это через аккаунт без ключа не удалось. Подписки и пополнение баланса
не выполнялись.
