# Поздравление Деда Мороза: собственный Instant-клон HeyGen

Раздел доступен только `ADMIN_USER_ID`, независимо от `STUDIO_ENABLED`.
Остальные пользователи видят заглушку. Озвучка и анимация Деда Мороза теперь
используют HeyGen. Fish Audio отключён, его адаптер удалён. Сценарии мультстудии,
Yandex TTS, песни, открытки, тарифы и платежи не меняются. Модуль ElevenLabs сохранён.

## Настройка и обновление

```dotenv
HEYGEN_API_KEY=
DED_MOROZ_HEYGEN_VOICE_ID=3146577ad1e544c1a4658ded1090740c
DED_MOROZ_TTS_MODEL=heygen-voice-1
DED_MOROZ_SPEECH_SPEED=0.90
DED_MOROZ_ECHO_DELAY_MS=55
DED_MOROZ_ECHO_DECAY=0.10
```

Используется существующий `HEYGEN_API_KEY`. ID по умолчанию — именно
`3146577ad1e544c1a4658ded1090740c`: «Дед мороз», Instant, `ru`.
Администратор подтвердил через список собственного workspace статус `ACTIVE`.
Старые `DED_MOROZ_VOICE_ID` ElevenLabs и `FISH_AUDIO_*` в этом сценарии не читаются.
Отдельное имя переменной предотвращает случайную подстановку ID другого провайдера.
Ключ не коммитить и не отправлять в чат. После обновления кода/окружения:

```bash
cd ~/Bot-Max
git pull --ff-only
systemctl restart botmax
```

Модель по умолчанию остаётся `heygen-voice-1`. Доступны явно выбранные
`heygen-voice-1-turbo`/`heygen-voice-1-turbo-free`; автоматического переключения
между моделями или голосами нет. Перед синтезом GET
`/v3/models/audio/voices/{voice_id}` проверяет точный ID, `ACTIVE` и `mode=instant`.
Новый клон не создаётся. Проверка доступа сама по себе не генерирует аудио.

Нужны существующие `STORAGE_*`, `STUDIO_FILES_DIR` и `ADMIN_USER_ID`.
Для проверки MP3 используется установленный `ffprobe` из FFmpeg.
Медиа для видео:

```
examples/ded_moroz_ref.png       # не нужен при готовом DED_MOROZ_AVATAR_ID/REF_URL
examples/fire_overlay.mp4       # необязателен
examples/audio/jingle_bells.mp3
examples/audio/ny_music.mp3
```

Отсутствующий огонь пропускается при монтаже с записью в журнал.
Музыкальные файлы и референс аватара проверяются только после одобрения аудио.

## Сбор данных, синтез и прослушивание

Последовательно собираются имя ребёнка, увлечение, достижение, качество,
задание и фото JPG/PNG. Шаблон, пояснения и фото сохраняются в SQLite и S3;
Pillow проверяет содержимое изображения и прежние лимиты 20 МиБ / 40 Мп.
Заказ использует собственную неизменяемую копию фото; повторная озвучка
не требует повторной загрузки.

Текст начинается с «Охо-хо-хо!». Сохраняются имя, факты, русский текст и
поддерживаемые HeyGen-теги `[deep voice]`, `[raspy]`, `[warm]`, `[pause]`,
`[drawls]`, `[slightly excited]`, `[proud]`, `[serious]`, `[reassuring]`.
Случайное соседнее «ты ты» исправляется. Низкая и слегка хрипловатая подача
чередуется с тёплыми/эмоциональными фразами. Неподдерживаемого тега
«старческий голос» нет: возраст и точное звучание зависят от самого клона
и оцениваются при прослушивании.
В предпрослушивании текст показывается без служебных тегов.

Текст общего шаблона, знаки препинания и места `{name}`, `{fact1}`, `{fact2}`,
`{fact3}`, `{task}` сохранены. Конкретные имена и факты не записываются в общий
шаблон: их подставляет прежний сценарий при создании поздравления.
Разметка обновлена: `[drawls]` стоит перед окончаниями «очень порадовал»,
«очень горжусь», «всё получится», «очень особенное», именем и финальным словом.
`[slightly excited]`, `[proud]`, `[reassuring]` задают эмоциональные переходы.
Два тега подряд не используются; `[drawls]` — подсказка модели, а не точная
гарантия скорости отдельного слова.

Стандартный старый шаблон получает новые теги только при явной перегенерации.
Произвольные пользовательские тексты и собственные правки тегов не заменяются.
Фото и имена сохраняются; начальное «Охо-хо-хо!» остаётся частью шаблона.

Синтез: `POST /v3/models/audio/tts`, `X-Api-Key`, подтверждённый `voice_id`,
`model=heygen-voice-1`, `language=ru`,
`output_format={encoding:mp3,sample_rate_hertz:44100,bitrate_bps:192000}`.
Параметры `speed` и `pitch_shift` не отправляются: Instant-клон их игнорирует.
Ошибки TTS HTTP 400 сохраняют полный диагностический текст в серверном логе,
с маскированием API-ключа, если провайдер его повторит в ответе.

HeyGen возвращает `audio_url`. Ссылка немедленно сохраняется в файле
`{order_id}/speech-vN.heygen-source.json`, до скачивания MP3. Потом сохраняются
`speech-vN.raw.mp3`. Затем FFmpeg создаёт отдельный
`speech-vN-delivery-HASH.mp3` и `speech-vN-delivery-HASH.heygen.json`:
хеш запроса/файла, параметры эффектов, их хеш и фактическая длительность.
Исходный MP3 сохраняется без изменения. Изменение текста, голоса или модели запрещает
использовать несовместимый кэш; новая попытка получает новую версию.

Повтор скачивания использует сохранённый URL без нового синтеза. При аварии
после сохранения URL или готового MP3 worker восстанавливает безопасный этап.
Неопределённый платный POST без сохранённого результата автоматически не повторяется.
S3 и доставка MAX отделены от синтеза. В архиве хранятся `provider=heygen`,
voice ID, модель, исходный/отправленный текст, хеш запроса, пути и публичные ссылки.

## Темп и лёгкое эхо

Обработка выполняется **до** предпрослушивания и передачи MP3 в HeyGen Avatar IV:

- `DED_MOROZ_SPEECH_SPEED=0.90` — примерно на 10% медленнее, через FFmpeg `atempo`,
  без искусственного понижения высоты тона. Допустимый диапазон 0.5–2.
- `DED_MOROZ_ECHO_DELAY_MS=55`, `DED_MOROZ_ECHO_DECAY=0.10` — один тихий
  короткий отражённый сигнал через `aecho`, без длинного эха. Допустимые
  диапазоны: 0–150 мс и 0–0.3; ноль отключает эффект.

Низкая/хрипловатая подача задаётся тегами на этапе синтеза, а не искажением
MP3. Неподдерживаемые числовые тембр/возраст в API не отправляются.
Настройки эффектов входят в отдельный хеш выходного файла. Повторная обработка
той же версии при изменении только эффектов использует сохранённый raw MP3
и URL без нового запроса TTS; исходник и предыдущие варианты сохраняются.
Явная кнопка **перегенерации озвучки** создаёт новую версию синтеза, как прежде.

Сохранённый/утверждённый ранее MP3 автоматически не меняется. Для проверки
новой подачи после обновления нужно явно перегенерировать озвучку. После
одобрения в Avatar IV и монтаж передаётся именно замедленный MP3 с эхом,
поэтому длина видео и синхронизация соответствуют фактическому аудио.

Администратор получает native audio и сообщение
«🎧 Прослушайте озвучку Деда Мороза. Всё нравится?» с кнопками:

- `dm_audio_approve` — утвердить точный файл и начать видео;
- `dm_audio_regenerate` — новая платная версия озвучки;
- `dm_audio_edit` — изменить текст и создать новую озвучку.

Попытки администратора не ограничены. Счётчик `regeneration_attempts` сохраняется;
в журнале — «Перегенерация аудио для USER_ID. Попытка: N».
Старые/двойные нажатия не создают дубликаты. Для будущих обычных пользователей
сохраняется одна общая повторная попытка, но публичный доступ не открывается.

## Остановившийся заказ manual

При повторном входе вместо общей строки `manual` показывается карточка.
Для остановленной озвучки до создания видео доступна кнопка
**«🎙 Перегенерировать озвучку»**. Текст карточки предупреждает о новой платной
попытке. Только после нажатия администратора, проверки конфигурации и наличия
сохранённого фото заказ атомарно переводится в новую версию `audio_queued`.
Текст/фото и старые версии сохраняются. Подтверждение с прежней версии не действует.
Это применимо и к старому `audio_submitting:HeyGenError` после смен провайдера.

Кнопка не перезапускает этапы видео и не меняет чужие заказы. Для остальных
остановленных этапов остаётся `/dm_resume ID`. 401/402/403/404/429 дают понятную
причину; известное отклонение позволяет явный повтор после исправления проблемы.
Таймаут/обрыв после POST без сохранённого ответа требует сверки у HeyGen.
Поддерживаются конечные таймауты; весь цикл синтеза ограничен 240 секундами.

## Видео и сохранность

При одобрении фиксируются `approved_audio_url` и `approved_audio_path`.
Именно они используются в HeyGen Avatar IV и в монтаже. Формат запроса видео:
`POST /v3/videos`, `type=avatar`, сохранённый look ID, утверждённый `audio_url`,
`engine.type=avatar_iv`, `aspect_ratio=16:9`, `resolution=1080p`.
Photo Avatar создаётся только при необходимости, после одобрения аудио;
изображение ребёнка используется лишь в локальном PiP, не в создании аватара.

FFmpeg измеряет фактическую длину утверждённого MP3 и выравнивает видеоряд,
начало речи — с нуля. Сохраняются музыка, PiP с рамкой на 30–70% длины, титр
«Для {name} от Деда Мороза» в начале и необязательный огонь. Выход:
MP4 H.264/AAC, 1920×1080, 30 FPS. Готовый MP4 отправляется как native video,
`dm_video_created` учитывается один раз после подтверждённой доставки.

Готовые старые аудио/видео Fish Audio, ElevenLabs и HeyGen не удаляются и
автоматически не перегенерируются. Для нового голоса на уже готовой озвучке
нужно явно нажать перегенерацию. Сохранённые этапы публикации/доставки продолжаются.
Рекомендуется резервная копия SQLite и всей `studio_files` перед обновлением.

Документация: [TTS](https://developers.heygen.com/docs/voices/heygen-voice-speech.md),
[состояние голоса](https://developers.heygen.com/reference/get-an-audio-voice),
[аудио в видео](https://developers.heygen.com/audio-to-video.md).
Ключ в доступном окружении разработки отсутствует. Новые платные генерации,
создание клона, аватара и реальные сообщения MAX при разработке не запускались.
