# Административное поздравление от Деда Мороза

Функция доступна только `ADMIN_USER_ID`, независимо от `STUDIO_ENABLED`.
Для остальных пользователей кнопка `cat_ded_moroz` показывает заглушку и «Назад».
Тарифы, покупки и балансы существующих услуг не меняются.

## Настройка рабочего сервера

Используются существующие `ADMIN_USER_ID`, `YANDEX_TTS_API_KEY` и параметры
Yandex Cloud `STORAGE_*`. Добавить в окружение сервиса:

- `HEYGEN_API_KEY` — API-ключ HeyGen (не OAuth).
- `DED_MOROZ_AVATAR_ID` — необязательно: ID **готового look**, не группы аватаров.
- `DED_MOROZ_REF_URL` — необязательно: публичный HTTPS URL референса Деда Мороза.
- `STUDIO_FILES_DIR` — существующая папка исходников, по умолчанию `studio_files`.

Ключи задаются на сервере, не в сообщении боту. После изменения окружения
нужно перезапустить сервис. Настройка платежей Prodamus для этой функции не нужна.

Файлы для этапа видео (озвучка от них не зависит):

```
examples/ded_moroz_ref.png       # не нужен при готовом look ID или REF_URL
examples/fire_overlay.mp4       # необязателен
examples/audio/jingle_bells.mp3
examples/audio/ny_music.mp3
```

**Сами медиафайлы в этот PR не входят:** их нет среди доступных исходников.
`fire_overlay.mp4` может содержать огонь/гирлянды на подходящем фоне для screen.
Его наличие проверяется только в монтаже: если файла нет, огонь пропускается
с предупреждением в журнале, готовое видео всё равно создаётся.
Собственный снег программа не добавляет.

До TTS проверяются только ключ SpeechKit, параметры S3 и сохранённое фото.
HeyGen, референс аватара, музыкальные файлы и FFmpeg/ffprobe для озвучки не нужны.
После утверждения аудио проверяются настройки HeyGen, обязательные музыкальные
файлы, референс (если ещё нет готового аватара) и инструменты монтажа.
Отсутствие этих обязательных компонентов останавливает только этап видео,
а отсутствие огненного оверлея не останавливает ни один этап.

## Сценарий в боте

1. Администратор нажимает «Поздравление Деда Мороза».
2. Сначала приходит одно приветствие «Добро пожаловать в мастерскую Деда Мороза!»
   с вопросом об имени/ласковом обращении. Технического сообщения про SpeechKit нет.
3. После имени приходят объяснение и **полный шаблон** с `[ИМЯ]`, `[УВЛЕЧЕНИЕ]`,
   `[ДОСТИЖЕНИЕ]`, `[КАЧЕСТВО]`, `[ЗАДАНИЕ]`, затем вопрос об увлечении.
   Далее последовательно запрашиваются достижение, качество и задание.
   Каждый вопрос содержит фрагмент шаблона
   и согласованные примеры в правильной форме. Фраза вставляется целиком,
   без изменения падежа или генерации дополнительного текста.
4. Фото JPG/JPEG или PNG отправляется через «Файл». Содержимое проверяется
   Pillow: максимум 20 МиБ и 40 000 000 пикселей; расширение и MIME не заменяют
   проверку формата. WEBP не маскируется под JPG: бот попросит исходный файл.
5. Сохраняются исходник, нормализованный PNG и публичный URL S3.
   Копия последнего фото лежит в `studio_files/ded_moroz_{user_id}/child_photo.png`.
   Заказ использует собственную неизменяемую копию `studio_files/{order_id}/...`,
   поэтому новая фотография не подменяет старую в выполняющемся монтаже.
6. После фото приходит «🎙 Генерирую озвучку Деда Мороза. Это займет около минуты...».
   Создаётся TTS SpeechKit v1: `filipp`, `good`, `0.95`, MP3. В form-urlencoded
   запросе используется `Authorization: Api-Key ...`, без `folderId`.
7. Администратор получает аудио, полный текст и кнопки `dm_audio_ok` / `dm_audio_edit`.
   Они связаны с ID сообщения MAX и версией озвучки в SQLite.
8. Правка доступна **один раз** и сохраняется в БД, даже после перезапуска.
   Новый текст создаёт отдельный MP3 версии 1; исходная версия остаётся в архиве.
   Старые кнопки не могут подтвердить новую версию. После правки остаётся только
   «Всё верно, создать видео». Это подтверждение запуска платных запросов HeyGen.

Перед фото используется сообщение «📸 Отправьте фотографию ребёнка. Она появится
в видео на несколько секунд. Лучше всего подойдёт чёткое фото анфас».
При запросе единственной правки явно указана платная перегенерация TTS.
В одном административном диалоге одновременно ведётся один активный заказ;
повторный вход продолжает его вместо создания нового платного заказа.

## HeyGen и очередь

API v3, `X-Api-Key`, `Idempotency-Key` для мутаций:

- Создание Photo Avatar: `POST /v3/avatars`, `type=photo`, `file.type=url`.
  Сохраняются **avatar_item.id (look ID)** и avatar_group.id. Создание выполняется
  только после утверждения аудио и один раз, а не при каждом старте бота.
- Опрос `GET /v3/avatars/looks/{look_id}` до `completed`.
- `POST /v3/videos`: утверждённый `audio_url`, сохранённый look ID,
  `engine.type=avatar_iv`, 16:9, 1080p, expressiveness=medium.
- `GET /v3/videos/{video_id}` до `completed`, затем загрузка MP4.

В HeyGen передаётся референс Деда Мороза; фото ребёнка используется только
при локальном наложении PiP. Для каждого заказа сохраняются текст, версии,
публичные ссылки, пути и provider ID. Очередь работает последовательно в
одном процессе сервиса и не блокирует обычные пользовательские разделы.
Кнопки подтверждения и правки используют атомарные переходы SQLite.

Документация контрактов: [Photo to Avatar](https://developers.heygen.com/docs/avatar-from-photo),
[Audio to Video](https://developers.heygen.com/audio-to-video.md),
[Create Video](https://developers.heygen.com/reference/create-video.md),
[Get Video](https://developers.heygen.com/reference/get-video.md).

## Монтаж и доставка

FFmpeg сохраняет MP4 H.264/AAC, 1920×1080, 30 FPS, yuv420p, faststart.
Основа — скачанный HeyGen MP4. Одобренный MP3 используется как основная речь,
начиная с нуля; конечная длина определяется полной озвучкой. При коротком видео
удерживается последний кадр. Голос не обрезается и не ускоряется.

- Огонь на весь экран через screen, если файл есть; иначе запись в лог и монтаж без огня. Снег не генерируется.
- Прямоугольное фото справа внизу: ширина около 480 px (четверть экрана),
  высота до 900 px с сохранением пропорций, белая рамка,
  показ с 30% до 70% длины.
- Jingle Bells: первые 3 секунды, громкость 0.4.
- Фоновая NY music: циклически, громкость 0.2.
- Речь: громкость 1.0; `amix normalize=0`, ограничитель против перегруза.
- Титр «Для {name} от Деда Мороза»: первые 5 секунд.
  Имя передаётся через UTF-8 textfile с `expansion=none`, без интерполяции
  пользовательских символов в выражения FFmpeg.

Готовый MP4 сохраняется локально и в S3, затем отправляется как **video**.
Токен загрузки MAX переиспользуется при `attachment.not.ready`/сбое доставки.
После подтверждённой отправки атомарно учитывается `dm_video_created`.
В `/stats` этот административный счётчик показывается отдельно, включая
производство администратора. Повторная доставка счётчик не увеличивает.

## Перезапуск и восстановление

Таблицы `ded_moroz_orders` и `ded_moroz_avatar` добавляются через `init_db()`.
Рекомендуется обычная резервная копия всей SQLite-базы и `studio_files`.

Сбой S3, опроса, локального монтажа или MAX повторяется без нового TTS/видео POST.
Истёкшая ссылка скачивания HeyGen обновляется безопасным повторным GET.
Если процесс прерван во время платного POST без сохранённого ответа, заказ
становится `manual`. **Автоматически повторять такой запрос нельзя.**
Проверить результат в кабинете/логах провайдера по ID/ключу идемпотентности.

Администратор может выполнить `/dm_resume ID_заказа`:

- При известном video_id продолжится GET-опрос прежнего видео.
- Без video_id восстанавливаются только безопасные сохранённые этапы
  или подготовка, на которой POST ещё не начинался.
- Неопределённый платный запрос без сохранённого ID остаётся заблокированным
  до ручной сверки. Слепое повторное начисление/запуск не выполняется.

Возможен повтор самого сообщения MAX при аварии между его отправкой и записью
подтверждения в SQLite; это не вызывает новую платную генерацию.

Реальные платные запросы, создание аватара и сообщения MAX при разработке не
запускались. Тесты используют HTTP-подмены, настоящие модели событий SDK MAX
и синтетические локальные медиа для проверки FFmpeg.
