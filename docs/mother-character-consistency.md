# Один утверждённый персонаж во всём мультфильме

## Причина и изменение

В старом шаблоне одновременно с портретом клиента задавались `grey or natural hair`, `cream cardigan`, `pearl earrings`, `necklace` и универсальный stylized 3D стиль. Эти признаки могли конфликтовать с утверждённым изображением. Кроме портрета, последующим сценам передавались первый сгенерированный кадр и финальный кадр предыдущей анимации. Если лицо уже изменилось, дополнительные изображения содержали другую внешность.

Новая версия сценария использует **единственный визуальный референс — чистый утверждённый портрет** для каждого из шести кадров. Промпт сохраняет его лицо, возраст, форму/цвет глаз, цвет и длину волос, одежду, рисунок ткани, аксессуары и степень реалистичности. Готовые сгенерированные лица не подмешиваются в новые кадры. Общая квартира и состояния предметов описаны одинаково в тексте сценария. В анимацию поступает соответствующий кадр, с запретом изменения лица/возраста/одежды и с закрытым ртом. Это улучшение управления генерацией, **не автоматическая биометрическая проверка сходства**: новые картинки и ролик нужно визуально проверить.

Новые policies:

- День матери: `mother-approved-identity-six-ten-second-shots-v3`;
- день рождения мамы: `mother-birthday-approved-identity-six-shots-v2`.

Песня, согласованный текст, оплата, шесть сцен по 10 секунд и фактическая сохранённая отметка начала песни не меняются. У конкретного исправляемого заказа отметка 13 с должна сохраняться, чтобы оставить около двух секунд музыки перед словами, начинающимися на 15-й секунде. Это индивидуальная отметка, а не новый default для всех клиентов.

## Совместимость и стоимость

`mother_storyboard_legacy_v2.py` сохраняет прежний сценарий и policies. Уже начатые/завершённые заказы продолжают свою версию, используют сохранённые prompts/ID/результаты. Старые семисценные заказы также поддерживаются. Обновление не сбрасывает картинки, не запускает перегенерации и не заменяет выданное клиенту видео автоматически.

Для исправления готового ролика создаётся явная **новая визуальная ревизия**. Исходное видео, все прежние картинки/ID анимаций/ссылки сохраняются в `cartoon_kling_story_archive`; музыка, утверждённый портрет и проверенное начало песни используются повторно. Клиенту не создаётся новый счёт. Новые картинки и анимации являются новыми платными запросами к провайдерам после запуска продолжения; существующие ID не выдаются за бесплатную перегенерацию.

Никакие реальные материалы клиента не добавлены в репозиторий. Проверка выполнена на синтетических URL/БД и поддельных провайдерах. Новая реальная генерация и визуальная проверка результата на сервере ещё не выполнены.

## Безопасная подготовка ревизии — сервер, после установки PR

Сначала только чтение плана, без backup, изменения БД, сообщений клиенту или API-запросов:

```bash
cd /root/Bot-Max
venv/bin/python -m mother_story_revision --database /root/Bot-Max/database.sqlite3 --order-id ORDER_ID
```

После проверки правильного заказа и решения пересоздать его визуальные сцены:

```bash
venv/bin/python -m mother_story_revision --database /root/Bot-Max/database.sqlite3 --order-id ORDER_ID --prepare
```

`--prepare` работает только с завершённым оплаченным заказом ко Дню матери/рождению мамы и подтверждённым началом сохранённой песни. При неизвестном результате прошлого запроса сцены, изменившейся песне или несовпадении утверждённого портрета команда останавливается. Она создаёт согласованную SQLite backup с правами 0600, архивирует старые визуальные данные и атомарно обновляет только этот заказ с проверкой прежних данных (CAS). Сумма, paid_at, payment ID, исходный портрет и ссылки на песню не меняются. Повторный `--prepare` не создаёт ещё одну ревизию поверх подготовленной.

Статус становится `manual`, новая ревизия готова к штатному восстановлению. Генерация **ещё не запускается**. Прежняя кнопка клиента «Проверить оплату / продолжить» восстановит заказ в памяти бота через существующий `recover_order`, затем продолжит его с сохранённой песней и новой визуальной версией. Не использовать новое оформление заказа/новый счёт и не сбрасывать FSM вручную. До запуска не обещать клиенту, что новый ролик уже готов.

Резервная копия содержит данные всего бота: хранить на сервере с ограниченным доступом, не публиковать и не пересылать в открытом чате. Старое видео остаётся в архиве ревизии и backup; не удалять его до проверки и принятия нового результата.

## Проверки

Тесты проверяют один и тот же master для всех новых сцен без дополнительных лиц, отсутствие навязанных признаков, старые policies/референсы и повторное использование оплаченных ID, создание новой ревизии без изменения исходника/музыки, сохранение отметки 13 с без повторного распознавания, read-only план, backup, CAS-подготовку и отказ от неизвестных/повторных операций. Остальные проверки материалов/песен/возобновления/вариантов и продаж запускаются вместе с новыми тестами. Все генераторы в тестах поддельные.

Итоговый целевой прогон: **134 passed**, 15,08 с, в восьми файлах тестов Mother-сценариев, включая 14 новых проверок. `compileall` изменённых Python-модулей прошёл. Проверен также отказ CAS при изменении заказа между backup и обновлением. Полный legacy-набор всего бота в рамках этого изменения не запускался; реальная генерация изображений/видео не выполнялась.

Дополнение для остановившихся до первого визуального запроса заказов: совершенно пустая старая шестисценная версия с тем же утверждённым портретом может автоматически перейти на новую identity policy при продолжении. Материалы и ID уже начатых сцен этим переходом не удаляются. Правило песни для двух минутных Mother-сценариев описано в `docs/mother-fixed-song-intro.md`.
