# Общее правило начала песни для двух мульт-открыток

По указанию владельца для минутных мульт-открыток **«День матери»** (`theme_mother`) и **«День рождения мамы»** (`theme_mother_bday`) применяется фиксированное начало фрагмента **13 секунд**. Если в исходном исполнении слова начинаются на 15-й секунде, в видео остаются примерно две секунды музыки.

## Что меняется

- Для этих двух сценариев распознавание Whisper больше не вызывается. Отсутствие первой строки в транскрипте и ошибочные таймкоды не блокируют сборку и не требуют повторных запросов распознавания.
- Отметка сохраняется с методом `mother-fixed-intro-v1`, ссылкой на конкретную выбранную песню и хешем текущего текста. Это заданное правило монтажа, а не результат распознавания.
- Подтверждённая администратором ручная отметка для той же песни/текста сохраняется. Отметка другого исполнения не переносится. Администратор может скорректировать фиксированную отметку штатным механизмом ручного начала.
- Новая визуальная ревизия тоже учитывает правило 13 с: прежняя автоматическая отметка остаётся в архиве старого ролика, а ручная отметка для той же песни сохраняет приоритет. План ревизии показывает ту же отметку, которую использует сборка.
- Музыка, голос, слова и фото не генерируются заново при возобновлении. Существующий готовый результат возвращается из кэша без платных запросов.
- Перед созданием картинок/анимаций проверяется фактическая длительность аудио: после отступа должна оставаться минута, то есть для 13 с нужна запись не короче 73 с. Слишком короткая песня останавливает процесс до расходов на сцены; автоматически покупать/генерировать другую песню нельзя.

**Важно:** сейчас код бота создаёт новое музыкальное исполнение для каждого заказа. Зафиксирован шаблон текста, а не единый общий MP3 для всех клиентов. Один и тот же текст не гарантирует одинаковый момент вступления голоса. Фиксированные 13 с введены как явно выбранное владельцем правило для этих продуктов. Если исполнение/аранжировка изменится и голос начнётся раньше, такой отступ может срезать слова; это нужно проверить на новых реальных записях. Другие песни, музыкальные открытки, новогодние/иные мульт-открытки и старые семисценные версии не переводятся на 13 с.

## Внешность и сохранённые заказы

Исправление единого персонажа из PR #259 применяется обоим новым сценариям: один утверждённый портрет во всех шести сценах, без навязанной одежды/возраста и дополнительных сгенерированных лиц.

Дополнительно старая шестисценная версия может безопасно перейти на новую policy **до любых визуальных запросов**: только если все шесть записей сцен совершенно пусты, утверждённый master совпадает с сохранённым источником, нет готового результата или платных task ID. Сохранённая песня/ручная отметка остаются. Переход фиксируется checkpoint до первого платного запроса.

Если есть хотя бы картинка, флаг отправки, task ID или видео, policy и существующие материалы автоматически не сбрасываются. Для завершённых роликов с неверной внешностью остаётся явная ревизия `mother_story_revision` из PR #259 с backup и архивом; все уже выданные видео автоматически не пересоздаются.

## Старые остановки на распознавании

Для оплаченного заказа в `manual`, остановившегося только на распознавании, клиент может нажать **старую кнопку «Проверить оплату / продолжить»**. Штатный `recover_order`:

1. проверит соответствие выбранной песни/текста известному сохранённому сбою;
2. убедится, что визуальные сцены не запускались;
3. сохранит 13 с и снимет устаревшую ошибку распознавания;
4. атомарно восстановит тот же оплаченный заказ и продолжит его.

Не создаётся новый счёт, не теряются фото/песня/платёж. Неизвестные результаты платных запросов сцен этим правилом не разблокируются. Ручные SQL-команды с фиксированным ID клиента для каждого нового случая не нужны. Простое обновление кода не запускает заказы фоном — требуется штатное продолжение.

## Проверки и установка

В тестах используются только временные БД, синтетические URL и mock-провайдеры. Проверяются оба праздника, отсутствие ASR, неверный кэш/исчерпанный бюджет распознавания, ручные отметки и смена варианта, короткое аудио до любых визуальных расходов, сохранение оплаченных ID и готовых результатов, безопасный переход пустых старых сцен и восстановление оплаты без повторного счёта.

После штатного применения PR и загрузки обновлённого кода в процесс бота проверить новый заказ обоих типов и старое продолжение. Не перезапускать процесс посреди активной отправки платных задач: сначала проверить очередь/сохранённые ID обычным рабочим порядком. В рамках разработки production/БД/бот не изменялись, реальные SMTP/музыкальные/ASR/видеозапросы не выполнялись. Новые реальные исполнения и визуальное сходство здесь не проверялись.

Итоговый целевой прогон: **179 passed**, 43,26 с, в десяти файлах тестов, включая 26 новых проверок фиксированного вступления. `compileall` изменённых модулей прошёл. Полный legacy-набор всего проекта в рамках этого исправления не запускался.
