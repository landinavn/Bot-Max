# Публичная витрина «Открытки и Карта желаний | Нейрофото»

Frontend 1.0. Отдельный каталог действующего MAX-сервиса; backend, авторизация, платежи и генераторы здесь не подключены. Ветка `feature/web-frontend` основана на `main` (`6cc6c10`). Изменения ограничены `web/`.

## Архитектура

React + TypeScript, Vite собирает клиентский JS/CSS. Отдельный build-time entry `src/prerender.tsx` использует `react-dom/server` и записывает полноценный HTML для каждого маршрута. `hydrateRoot` добавляет интерактивность уже отрендеренным страницам. Nginx может отдавать `dist/` как обычные файлы: Node.js в production не нужен. Маршрутизатор и анимационные библиотеки не добавлены; ссылки между страницами работают и без JS.

```
web/
  src/
    App.tsx          главная и шаблоны страниц
    components.tsx   шапка, каталог, FAQ, галерея, медиаплеер, сравнение
    catalog.ts       девять продуктов, индивидуальные тексты и источники тарифов
    config.ts        бренд, MAX, сезонный блок, медиакаталог, юридические слоты
    site.ts          маршруты и проверка доступности продуктов
    seo.ts           метаданные, robots, sitemap
    analytics.ts     интерфейс локальных событий и безопасные UTM
    entry.tsx        hydration
    prerender.tsx    статическая генерация
    styles.css       адаптивный дизайн
  public/media/      разрешённые реальные работы и постеры
  scripts/           локальный сервер QA и оптимизация разрешённых медиа
  tests/             статические и браузерные проверки
```

Все публичные маршруты имеют свой title, description и H1: `/`, `/postcards`, `/vision-board`, `/photosessions`, `/photosessions/new-year`, `/ded-moroz`, `/cartoons`, `/songs`, `/musical-postcards`, `/animation`, `/custom-order`, `/gallery`, `/prices`, `/blog`.

`/login`, `/account`, `/account/works`, `/account/balance`, `/account/settings` — честные заглушки будущего кабинета без сбора данных, входа, баланса или заказов. Неизвестные адреса должны получать `404.html` с HTTP 404.

## Локальный запуск и проверки

Node.js 24, npm 11. Выполнять вне production:

```bash
cd web
npm ci
npm run dev
```

При недоступном стандартном npm-кэше можно использовать `npm ci --cache /tmp/wish-npm-cache`.

Статическая сборка и проверки:

```bash
npm run build
npm test
node scripts/serve.mjs
# В другом терминале, пока статический сервер работает:
npm run test:browser
```

Браузерный тест ожидает Chromium по `/usr/bin/chromium`; можно указать `CHROMIUM_PATH`. Либо установите Chromium средствами своей ОС. Тест запускает headless-браузер; на доверенной изолированной CI-машине используется `--no-sandbox`. `WEB_TEST_URL` позволяет указать другой локальный origin без завершающего `/`. Скриншоты пишутся в игнорируемый `test-results/`, другой путь задаётся `WEB_SCREENSHOT_DIR`.

Тесты проверяют 19 маршрутов и 404, HTML без JS, SEO, внутренние ссылки/ресурсы, режимы продуктов, безопасные UTM, отсутствие известных шаблонов секретов, 7 ширин экрана (320–1920), галерею/диалог/возврат фокуса, сравнение мышью/клавиатурой/касанием, мобильное меню, FAQ и семейный вариант Деда Мороза. Браузерные внешние запросы блокируются. Реальные генерации и оплата не выполняются.

## Конфигурация и подключение backend позже

- `src/config.ts`: `maxUrl` взят из `config.py:DEFAULT_BOT_LINK` — `https://max.ru/se14596751_1_bot`. Используется обычный адрес без непроверенных deep links.
- `season` меняет новогодние предложения без переработки главной.
- `src/catalog.ts`: `max_redirect` направляет в MAX; `coming_soon` скрывает продукт из каталога и закрывает его страницу от индексации; `web_enabled` требует явного `site.webOrdering` и локального `webPath`. Сейчас этот режим намеренно запрещён валидатором. Позже он включается только вместе с настоящим API/маршрутом заказа.
- Фиксированные суммы не опубликованы: действуют акции и персональные условия. Источник тарифов и дата проверки (26.11.2026) сохранены в `pricing.source/reviewedAt`. Изучены `database.py`, `prodamus.py`, `ded_moroz_sales.py`; ID тарифа не принимается за его стоимость. Цены подтверждает MAX перед оплатой. Арифметики скидок или второй тарифной системы здесь нет.
- Общее ядро авторизации и платежей из других веток не импортируется. Следующий этап должен читать каталог и создавать реальные заказы через backend.

## Аналитика

`trackEvent` отправляет локальное событие браузера `wish:analytics`; внешних счётчиков и придуманных ID Метрики нет. Сейчас вызываются `product_view`, `product_click`, `gallery_view`, `max_redirect`. Имена `signup_started`, `generation_started`, `payment_started`, `payment_success` зарезервированы до реальных операций. Payload ограничен ID продукта/категорией, пользовательских текстов нет.

UTM сохраняются при первом переходе в `sessionStorage`: только пять стандартных ключей и короткие ASCII-slug значения. Произвольные тексты, email, URL и токены не сохраняются. В ссылку MAX UTM не добавляются. Перед подключением внешней аналитики нужны согласованные юридические условия и реальный ID счётчика.

## Медиа, SEO и ограничения перед запуском

Читайте `public/media/README.md`: источники, разрешения, недостающие файлы и повторяемая обработка. В Frontend 1.1 подключены реальные изображения, четыре видео и аудиофрагмент из согласованного мультфильма. `works/manifest.json` хранит происхождение файлов. Видео и аудио загружаются по нажатию, без autoplay. Неполные пары «до/после» честно обозначены; интерактивное сравнение работает только на подтверждённой паре. Оригинальный квадратный логотип и favicon подключены без изменения пропорций.

По умолчанию сборка `preview`: в HTML `noindex,nofollow`, robots запрещает весь сайт, sitemap пуст. Кабинет, login, пустой журнал и галерея до отдельного согласования индексации остаются закрыты и в будущей production-сборке. Production-режим (`WEB_BUILD_MODE=production npm run build`) заблокирован до явного изменения `site.readyForIndexing` после согласования материалов и запуска. Проверка находится в prerender; не использовать незавершённый `dist/` после намеренно отклонённой production-сборки. Внешний `X-Robots-Tag` Nginx эта конфигурация не меняет.

Владелец должен предоставить/подтвердить:

1. Исходный логотип; до него используется текстовое название.
2. Разрешённые для публикации hero, примеры каждой услуги, настоящие пары до/после, аудио и видео с постерами и правами на публикацию.
3. Контакты поддержки/владельца, реквизиты, оферту, политику конфиденциальности и согласие на обработку данных.
4. Юридически подтверждённые условия возвратов, хранения и обработки фото; никакие сроки и гарантии здесь не придуманы.
5. Согласование дизайна, окончательных текстов и состава доступных услуг. Материалы журнала для будущей индексации.

У страницы `/prices` пока нет фиксированных сумм. Автоматического входа/оплаты/загрузки фото на сайте нет. Полноценное воспроизведение реальных медиа невозможно проверить до получения файлов. Поиск известных шаблонов секретов в bundle дополняет ручную проверку исходников, но не является универсальным сканером утечек. Достоверные структурированные данные о товарах/предложениях добавляются вместе с подтверждёнными данными; рейтинги и отзывы не выдуманы.

## Предварительный план deployment — не выполнялся

1. После согласования собрать и проверить статический `dist/` на отдельной машине. Проверить источники, список файлов и SHA архива. Сборка/Node.js на VPS не нужны.
2. Сохранить текущую версию `/var/www/wish-app` и действующую конфигурацию Nginx. Передать архив в отдельный каталог релиза, проверить контрольную сумму и права файлов.
3. Отдельно согласовать обслуживание маршрутов: `try_files $uri $uri/ =404` с `error_page 404 /404.html`. Не делать SPA-fallback, превращающий неизвестные адреса в HTTP 200. Защитить открытие служебных файлов; публиковать только `dist/`.
4. Проверить HTTPS, URL/SEO/404, кэширование хешированных assets и небольшое время кэша HTML. При использовании атомарной ссылки на релиз иметь возможность вернуть её на предыдущую версию.
5. Сохранить существующий серверный `X-Robots-Tag: noindex` до отдельного разрешения публичного запуска и готовности юридических данных/медиа. Это отдельное действие, не часть PR.
6. Проверить ресурсный бюджет VPS и откат. Перезапуск бота, миграции БД, изменение платежей и платные API для размещения статической витрины не требуются.

Никаких изменений production, Nginx, БД, MAX-бота или действующих тарифов в рамках этой работы не делалось. Слияние PR и deployment не выполняются автоматически.
